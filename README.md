# iwork —— 个人随身资料库（先读我）

> 这是一份自包含的个人资料包。无论是什么 AI、在什么环境运行，只要用户把这个仓库给你，你就应该能看懂全部内容并执行里面的工作流。本文件是入口，请先通读，再按任务需要打开对应文档。

## 一、这是个什么库（背景，必读）

- 这是一个**个人随身业务资料库**，只围绕「养户走访 + 通威料转化」这一件事运转。整个库**只干这几件具体的事**，其余一律不碰：
  1. **测水**：收到水样比色管照片 → **目视比对 `比色卡/` 标准卡出数**（程序工具仅辅助筛查，外拍读数禁止直接采信）→ 出表 → 标异常 → 回写 `数据/水质检测记录.csv`（见 `工作流/01_水样测试工作流.md`）。
  2. **记录用户数据**：把走访得来的养户/客户信息沉淀进 `数据/` 三张表（摸牌表、档案、拜访流水），新增或更新都按 `工作流/02_客户名单管理工作流.md` 走。
  3. **流水日志**：白天随时把走访、测水、想到的点记进当天 `日志/YYYY-MM-DD.md`、`每日问题/YYYY-MM-DD.md`，只记录不汇总。
  4. **写每日工作总结（最重要）**：每天把当天走访整理成工作总结，发群里给领导看——**只输出、不落仓库**（见第四节第6条）。这是本库每天的收口动作，优先级最高。
- 核心用法：白天随时记录 → 傍晚 18:30 统一归纳进 `数据/` → 产出当日工作总结。
- 沟通语言：中文。所有产出（表格、名单、日报、总结）都用中文。

## 四、通用规则（任何任务都适用）

1. **数据与事实来源**：联系人的情况、检测读数一律以 `数据/` 里的文件为准；不要凭印象编造信息或读数。
2. **路径与格式保持一致**：路径用相对路径（相对本仓库根目录），不要假设绝对路径；每个文件的列结构、命名风格、分类口径都已定型，新增内容严格沿用。
3. **追加型文件只追加、不覆盖历史**：`水质检测记录.csv`、`养殖客户拜访记录汇总.xlsx` 只追加，不覆盖历史记录。
4. **名称权威与合并（严禁就名字提问）**：人名、经销商名、品牌/厂家名等一切名称，**一律以第一次录入本仓库时的写法为准**。后续再遇同音、近音、谐音或异写（如「丁志开/丁志杰」「田永均/田永军」「黄绍雄/黄少雄」），**直接沿用首次录入的写法**并入首条，可在备注注「同音变体：××」；**严禁向用户提问、核实、确认或请示任何名称写法**。本条对所有访问本仓库的 AI 生效，任何情况下都不要因名称问题打扰用户。
5. **不擅自定性**：日常联系一律记"客情走访"；"新联系人"由用户自己标注，AI 不主动下结论。
6. **按天建档：日志与每日问题（白天只记不汇总）**：每天新建 `日志/YYYY-MM-DD.md` 与 `每日问题/YYYY-MM-DD.md`，白天随时追加、只记录不汇总。写入一律优先当天日志/每日问题；涉及走访先读当天日志掌握尚未归纳的最新动态。每晚 18:30 统一把当天日志归纳合并进 `数据/用户摸牌表.xlsx` 和 `数据/养殖客户拜访记录汇总.xlsx`，并产出当天工作汇报；日志/每日问题保留存档。后续查信息一律先查摸牌表，不翻历史日志。
7. **文件修改与动表权限（内容说改就改，摸排表白天不动）**：修改已有文件内部内容（日志 MD 正文、Excel 单元格/字段、CSV 行内数据等），本人说改就直接改，无需二次确认。但**摸排表（用户摸牌表、档案、拜访汇总）白天一律不动物牌表**——当天收到的数据与摸排表对不上的（新增/改名/改品牌/改经销商/改等级等），先记到当天日志，等 18:30 归纳时统一处理；确有特殊情况须在非归纳时间上传摸排表，须先征得本人同意，不得擅自落盘。
8. **文件增删须两次确认**：在仓库目录里**新增或删除文件**（任何文件、照片或目录，如 `照片存档/` 里的图片），必须先列出清单，经本人**两次确认**后方可执行，不得擅自增删。
9. **依赖环境**：照片辅助筛查需要 Python + 图像/数值处理库；读写 xlsx 需要 pandas + openpyxl。环境缺库先安装再执行。读数出数以目视比对标准卡为准，无 Python 环境不影响出数。
10. **仓库公开纪律**：本仓库**刻意保持公开**，目的就是让任意 AI、任意对话都能直接访问并执行工作流；不要主动建议或询问"是否私有化/是否脱敏隐藏/是否改私有"等，也不要擅自做隐藏、删除或限制访问的操作。
11. **抓鱼期潜规则（不是纪律）**：用户抓鱼（出鱼）期间在忙、顾不上理人，这是行业常识。写每日汇报直接写「抓鱼，择日再访」就完事，不解释原因、别写"按纪律不拜访"；工作日志怎么记都行，但汇报出去要简洁。
12. **工作总结（发群、纯文本、不落仓库）**：工作总结是本人写、复制到群里给领导看的，不是仓库文件。AI 只负责整理结构并在聊天里输出给用户，严禁写入任何 MD / 仓库文件。输出只给可直接复制到微信/群聊的纯文本本身（"X月X日/事件/1…/心得"段落），前后不加任何说明性文字；报告要简洁（见第 11 条）。
13. **提醒边界（只报文件一致性问题）**：只在以下情形主动提醒本人——①系统性文件问题（重复内容被覆盖、被删减）；②文件之间、或文件与工作目录对不上（不自洽/不一致）。除此之外，业务/工作内容不额外发挥、不猜测、不啰嗦。
14. **新对话启动自检**：每次开启新对话、读完本文件后，先检测当天 `日志/YYYY-MM-DD.md` 是否记录当日走访，再检测 `数据/用户摸牌表.xlsx` 与 `数据/养殖客户拜访记录汇总.xlsx` 是否已归纳该日内容；若日志有内容但摸排表尚未归纳、且当前早于 18:30，则直接执行归纳（按第 6 条合并进数据表并产出汇报）；已归纳则跳过，不重复写。
15. **强制规则（日志以 GitHub 仓库为准，当日必建、涉及用户必扫描）**：凡涉及"日志"的操作，先检索 `日志/` 目录是否已有当日 `日志/YYYY-MM-DD.md`；**没有则必须在 GitHub 仓库新建当日日志**（本地只作临时检索，不在本地散落文件，最终落到 GitHub）。任何会话**涉及拜访/接触的用户姓名与情况**，必须**扫描全部 `日志/` 文件**确认是否已记录；未记录的，立即补记到当日日志，不得遗漏。
16. **强制定规（仓库内改 MD 规则 / 改日志：直接改并推送 GitHub，不问）**：用户在仓库内要求**修改任何 MD 规则文件**（含本 README、`工作流/` 下 MD 等）或**改日志 MD**，AI 直接修改并**立即推送 GitHub**，无需再询问"是否推送到 GitHub"；改日志同样直接落到 GitHub，不二次确认。本条与第 15 条共同确保仓库始终为最新权威。


17. **摸排表编写·通威用户跟进口径**：通威现有用户（客户分类「一、通威现有」）不要加强客情拜访，做好客情服务、沟通后续用料即可，不在此类已转化客户上投入额外攻坚精力；把拜访与转化资源留给高意向（二）与潜力（三）客户的攻坚。


18. **禁止克隆/下载仓库，API 速读即回报**：任何 AI 会话**不得把本仓库克隆或下载到本地文件系统**（如 `git clone`、整库下载到磁盘），以免新会话启动缓慢、拖慢响应。应通过 GitHub API（`curl -H "Authorization: token 密钥"`）直接读取 `README.md`、工作流、数据表结构、`模板与汇报/` 等文件，快速浏览掌握全部规则后，**立即告知用户"已读毕、可接任务"**，不要让用户空等。仓库地址与密钥由用户在使用时随提示词提供，不写死在仓库内。

## 六、常识速查

- **⚠️ 报警线**：检测值超过约定阈值即标 ⚠️；接近阈值的临界项也是回访的天然由头。
- 记录异常项时，优先标注数值与对象，便于后续跟进。

## 七、数据表功能定位（数据/ 各文件用途）

- **用户摸牌表.xlsx**：客户主摸牌表，全域一图看清。记每个客户的地理、规模、品牌、经销商、用量、包产、跟进。字段含客户分类（一通威现有、二高意向、三潜力培育）、地址基地、塘口数、面积、现用品牌、现有经销商、负责人、年用量、近期包产、跟进建议；自带分类统计 sheet，按三类汇总户数。
- **养殖客户档案.xlsx**：成功率定档档案。按卖料成功率给客户打 A–E 档看转化价值。字段含卖料成功率%、成功率等级（A已成交、B明确意向、C有潜力、D竞品粘性、E停养转出）、成功率依据、详细养殖情况、拜访次数。
- **养殖客户拜访记录汇总.xlsx**：拜访流水台账。每次拜访按日期和人名串起来的养殖情况流水。字段含日期、人名、养殖情况。
- **水质检测记录.csv**：测水原始记录。每口塘三项指标，记谁家、哪口塘、几点测。字段含用户、塘号、位置、日期、时间、pH、氨氮、亚盐、备注。

> 四者关系：摸牌表是客户全景（谁、在哪、怎么攻），档案表是成功率定档，拜访汇总是每次聊了什么的流水，水质 CSV 是测水硬数据。另有派生的客户卖料成功率排名.xlsx（由档案表生成），不在数据/ 实体文件中。


20. **硬性规则（日志必须实时写，18:30 延迟只针对摸排表、绝不针对日志）**：`日志/YYYY-MM-DD.md` 是**跨 AI 会话的实时共享记录**。所有 AI 会话一旦获取到任何用户名相关情况，**必须立即、及时追加写入当天日志，不得积压、不得等 18:30 才写**。本人规定「等到 18:30 再处理」指的是**统一归纳进摸排表等数据表**，而**不是**延后写日志。若日志不及时更新，其他 AI 会话读不到最新动态，会重复问、重复错。
21. **硬性规则（数据表 18:30 才动，且动之前必须先完整浏览当天日志）**：所有数据表的唯一改动窗口是每天 18:30；18:30 归纳前，AI **必须先完整读一遍当天 `日志/YYYY-MM-DD.md`**，以日志为唯一事实来源去归纳；**严禁在没读日志、仅凭对话记忆或你零散口述的情况下直接改写数据表**。先读日志、再动表，两者顺序不可颠倒。
