# 服务器部署与训练手册（比色管 YOLOv8）

> 面向：把这套比色管检测流程部署到**你自己的服务器**，自己准备数据、自己训练。
> 本文件与 `模型/README.md`（体系设计与现状）互补——README 讲"为什么"，本文讲"怎么在我机器上跑起来"。
> 所有命令均在**仓库根目录**执行（含中文目录，Ubuntu/macOS 直接可用）。

---

## 〇、十分钟快速开始

```bash
# 1) 拉仓库
git clone https://github.com/shengjunfu02-maker/iwork.git && cd iwork

# 2) 一键装环境 + 校验数据（Ubuntu/Debian 服务器）
bash 模型/setup_server.sh

# 3) 训练（CPU 也可，约 10–20 分钟 / 120 epochs）
source 模型/.venv/bin/activate
python 模型/train.py --epochs 120 --batch 8 --device cpu

# 4) 把训练出的权重接进推理
cp 模型/runs/train/tubes_v1/weights/best.pt 模型/weights/tubes_v1.pt
python 模型/infer.py 你的照片.jpg --weights 模型/weights/tubes_v1.pt --show /tmp/preview.jpg
```

## 一、环境要求

| 项 | 最低 | 说明 |
|---|---|---|
| Python | 3.9+（推荐 3.10–3.12） | `python3 --version` |
| 内存 | 4 GB（CPU 训练） | batch 调小即可 |
| 磁盘 | 3 GB | torch + ultralytics + 数据集 |
| GPU | 可选 | 有 NVIDIA GPU + CUDA 则把 `--device cpu` 换成 `--device 0`，快 20–50 倍 |
| 依赖 | `模型/requirements.txt` | ultralytics≥8.4 / torch≥2.0 / Pillow / numpy / matplotlib |

**两个必踩的坑（本仓库已有实测结论）**：

1. **系统 Python 受 PEP 668 管控**：新版 Debian/Ubuntu 直接 `pip install` 会被拒。
   → 用 venv（`setup_server.sh` 已自动处理）。
2. **ultralytics 首次运行会自动下载 `yolov8n.pt`**：若服务器在外网受限环境会卡住。
   → 本仓库**已随库分发** `模型/weights/yolov8n.pt`（6.5 MB，COCO 预训练，AGPL-3.0），
   train.py 直接指向它即可，无需联网下载。

## 二、手动装环境（不用脚本时）

```bash
cd iwork

python3 -m venv 模型/.venv
source 模型/.venv/bin/activate

# 验证
python -c "import ultralytics, torch; print(ultralytics.__version__, torch.__version__, torch.cuda.is_available())"
# 最后一项 True = 有 GPU 可用；False = 走 CPU
```

## 三、数据：格式与放置位置

数据集根：`模型/dataset/`，YOLO 检测格式（单类 `tube`）：

```
模型/dataset/
├── images/
│   ├── train/   ← 训练图片（.jpg）
│   └── val/     ← 验证图片（.jpg）
└── labels/
    ├── train/   ← 与图片同名 .txt
    └── val/     ← 与图片同名 .txt
```

标签文件每行一根管，全部归一化到 0–1：

```
0  x_center  y_center  width  height
```

示例（图片 1600×2133，某根管框在 x 300–520、y 700–1600）：

```
0  0.25625  0.53915  0.1375  0.42194
```

**规则**（完整口径见 `模型/data/标注规范.md`）：

- **一根管一个框**，框住整根可见部分（管口到管底），贴边、别留大块背景；
- **近无色/透明管必须标**（最容易漏检的一类，训练集不覆盖就永远学不会）；
- 被手/管壁遮挡的照标到可见部分；只入镜部分管就标部分管；
- train : val ≈ **8 : 2**，且**同一基地/同一批的照片不要跨集拆**（背景雷同会虚高指标）；
- 单类，类别号恒为 `0`。

**数据从哪来**：日常塘头测水照片即可。按 `标注规范.md` 的覆盖矩阵（管色/背景/视角/光照/管序）尽量铺满，目标 **50–100 张**。当前仓库已有 13 张 / 39 框作种子集。

## 四、标注工具推荐

| 工具 | 平台 | 说明 |
|---|---|---|
| [labelImg](https://github.com/HumanSignal/labelImg) | Win/Mac/Linux | 直接输出 YOLO txt，最省事 |
| [AnyLabeling](https://github.com/vietanhdev/anylabeling) | Win/Mac/Linux | labelImg 升级版，带 AI 辅助预标注 |
| [Roboflow](https://roboflow.com) | 网页 | 在线标注 + 导出 YOLOv8 格式（注意免费额度公开数据集） |
| [X-AnyLabeling](https://github.com/CVHub520/X-AnyLabeling) | 桌面 | 内置检测模型自动预标注，**最适合本项目**：先用现有 `weights/yolov8n.pt` 预标再人工修 |

**预标注加速技巧**（强烈推荐）：
```bash
# 用当前权重先批量出框，再人工修 → 省 80% 人力
python 模型/train.py 的推理侧或直接:
yolo predict model=模型/weights/yolov8n.pt source=你的照片目录/ conf=0.25 save_txt=True save_conf=True
# 产出的 labels/*.txt 直接改名放进 模型/dataset/labels/train/，再用标注工具微调
```

## 五、训练

```bash
source 模型/.venv/bin/activate      # 进环境

# 标准训练（CPU）
python 模型/train.py --epochs 120 --imgsz 640 --batch 8 --device cpu --name tubes_v1

# 有 GPU（如 RTX 4090）
python 模型/train.py --epochs 200 --imgsz 640 --batch 32 --device 0 --name tubes_v2

# 从已有权重继续训（增量数据后）
python 模型/train.py --model 模型/weights/tubes_v1.pt --epochs 80 --name tubes_v3
```

**关键参数**：

| 参数 | 默认 | 建议 |
|---|---|---|
| `--epochs` | 120 | 数据 <50 张：100–150；>100 张：200–300 |
| `--imgsz` | 640 | 管在画面中占比小就提到 960/1280（更准但更慢） |
| `--batch` | 16 | CPU/小内存用 4–8；GPU 用 16–32 |
| `--device` | cpu | 有卡填 `0` |
| `--model` | yolov8n.pt | n 最快；数据多了可换 `yolov8s.pt` 提精度 |

产出：`模型/runs/train/<name>/weights/best.pt`，同时 `runs/detect/...` 下有混淆矩阵、PR 曲线等图表。

**训完必做**：`cp 模型/runs/train/<name>/weights/best.pt 模型/weights/<name>.pt`，infer.py 默认不认 runs 目录。

## 七、日常迭代闭环

```
塘头拍照 → 入库 dataset/images → 用现权重预标注 → 人工修框 → 训练 → 回归验证 → 更新 weights
```

- 每攒 **20–30 张新图**重训一次，通常能明显提升；
- 每次重训后跑一遍已知塘的回归（照片 + CSV 真值），记录命中率，**下降就回滚权重**；
- 数据、权重、训练记录都进 Git（权重 6 MB 级可入库，>100 MB 用 Git LFS）。

## 八、红线（务必遵守）

1. 模型输出是**辅助初判**，外拍照上**不得直接作为读数汇报**——与人眼/地面真值矛盾时以人眼为准，记录备注"人眼锚定"（见 `工作流/01` 避坑#6）；
2. 不是比色管的图不硬读；
3. **同一批照片不跨 train/val 拆**，否则指标虚高、上线打脸；
4. 改了推理行为，同步更新 `工作流/01` 与 `工具/water_toolkit.py` docstring。

## 九、常见问题

| 现象 | 原因 / 解决 |
|---|---|
| `pip install` 报 `externally-managed-environment` | PEP 668，用 venv（`setup_server.sh` 已处理） |
| 训练卡在 "Downloading yolov8n.pt" | 外网受限，改 `--model 模型/weights/yolov8n.pt` |
| `data.yaml` 找不到图片 | 必须在**仓库根目录**运行（train.py 会自动把 path 改绝对路径兜底） |
| CUDA out of memory | 调小 `--batch`（4），或 `--imgsz 640` |
| 中文路径报错 | 本仓库已实测支持；若系统 locale 异常，`export LC_ALL=C.UTF-8` |
| mAP 一直是 0 | 检查 labels 是否与图片**同名同目录**、是否归一化、类别号是否为 0 |
| val 指标很高但实测很差 | 同批照片被跨集拆分 → 重划 train/val |

## 十、与现有工具的关系

```
照片 ──► [本目录] YOLOv8 检测 tube ──► 每根管的紧致框
                │
                ▼
         infer.py：框内定位液柱 + 取代表色（复用 water_toolkit 口径）
                │
                ▼
         三族锚点定指标 → hsv_to_value 换算 + ⚠️ 预警
                │
                ▼
         读数初判（辅助）──► 人眼/地面真值仲裁（红线）
```

`工具/water_toolkit.py` 的色阶表、⚠️ 规则、亚盐外推、避坑清单**全部保留复用**，本目录只替换"检管 + 采样"两个原规则法失灵的环节。
